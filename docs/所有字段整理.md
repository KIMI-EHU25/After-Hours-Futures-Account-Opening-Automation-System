说明：

- 两个已经停用的只读字段未收入本文档。

- 下方 `data` 只保存页面注入数据，因此不包含 `uid`。
- 日期通过 JSON 传输时使用 `YYYY-MM-DD` 字符串，例如 `2026-03-03`。

## 接口对应关系

| 数据分组 | 请求接口 |
| --- | --- |
| `launderingBack` | `POST /api/launderingBack/answer` |
| `addInfo` | `POST /api/addInfo/answer` |
| `question` | `POST /api/question/answer` |
| `chooseFutures` | `POST /api/chooseFutures/answer` |

四个 POST 接口都需要以下请求头，服务端根据 Access Token 确定用户，答案请求体不传 `uid`：

```http
Authorization: Bearer <access_token>
```

登录、刷新及完整请求规则见 [接口文档](../service-api/api.md)。

## 可空字段与关联校验

- `p16`（邮箱）、`p22`（推荐人代码）、`p23`（推荐人姓名）可以为 `null` 或省略。
- `p6=true`（长期有效）时，`p4`、`p5` 必须为空或省略；`p6=false` 时，两项日期均必填，且结束日期必须晚于开始日期。
- `p19=true`（存在居间人）时，`p20`、`p21` 均必填且不能为空字符串；`p19=false` 时，两项必须为空或省略。
- 非空字符串去除首尾空白后不能为空；身份证需通过格式、出生日期和校验位验证，邮编为 6 位数字，联系电话为中国大陆手机号。
- 联系地址省市代码必须有效且匹配；职业、学历必须为有效代码。邮箱非空时需符合邮箱格式。

具体规则以 [addInfo Schema](../service-api/app/schemas/addInfo_schemas.py)、[addInfo CRUD](../service-api/app/cruds/addInfo_cruds.py) 和 [数据库结构](数据库表结构.md) 为准。

## 题目与作答字段详细说明

本节依据 `service-api/scripts/seed/seed_data.json` 中的题目、选项和字段配置整理。

题型及答案保存规则：

- `one-choice`：单选题，答案保存为一个选项代码字符串，例如 `"A"`。
- `multiple-choice`：多选题，答案保存为按选项顺序连接的代码字符串，例如 `"ABC"`。
- 风险测评题的“分值”来自 `questionoptions.value`。
- 补充资料中的 `int` 表示配置层面的代码型字段；这些代码通过当前 POST 接口提交时仍使用字符串，例如 `"156110000"`。
